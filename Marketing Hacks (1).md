# **What I would do instead**

The restaurant story isn't really about creating a journey.

It's about **engineering the next obvious interaction.**

That's a subtle but important difference.

The customer never feels like they're in a marketing funnel.

They simply think...

> "That makes sense.

> I'll do that next."

That's what we should build.

Instead of this...

Landing Page

↓

Choose Tool

↓

Done

We quietly evolve it into this...

Landing Page

↓

Choose Tool

↓

Tool solves problem

↓

Suggest ONE logical next step

↓

Tool solves another problem

↓

Suggest ONE logical next step

↓

Eventually AI Assessment

↓

Consultation

Nothing changes.

Nothing becomes more complicated.

We're simply making sure every successful experience creates another useful experience.

That philosophy is what I'd build into the platform.

Something like

**Progressive Value Journey**

**Next Best Step Framework**

## **The Momentum Framework**

Because that's exactly what's happening.

Every interaction creates momentum.

Never friction.

# **Below is the playbook I'd give an AI agent.**

# **Grow Local Business**

# **Momentum Framework Playbook**

## **Version 1.0**

---

# **Purpose**

The purpose of this framework is **not** to redesign Grow Local Business.

The platform already has a strong structure:

* Landing Page  
* Free Tools  
* AI Assessment  
* Consultation  
* Custom Solutions

This structure must remain.

The Momentum Framework exists for one purpose only:

> Increase the likelihood that someone who successfully uses one tool naturally chooses to use another.

No additional complexity should ever be introduced.

The experience should remain simple, lightweight and enjoyable.

Users should never feel that they are being moved through a sales funnel.

Instead, every recommendation should feel like genuinely helpful advice.

---

# **Core Philosophy**

Every completed interaction should answer one question.

> "What's the single most useful thing this business owner should do next?"

Only recommend one next action.

Never present multiple competing calls to action.

Momentum is created through clarity.

Not choice.

---

# **Design Principles**

The framework must always follow these principles.

## **Principle 1**

Solve today's problem first.

Never interrupt a user before they have achieved the reason they visited.

Example

Wrong

Generate QR

↓

Immediately promote AI Receptionist

Correct

Generate QR successfully

↓

Celebrate success

↓

Recommend the next logical improvement

---

## **Principle 2**

Recommendations must feel earned.

Never advertise another tool simply because it exists.

The recommendation must naturally follow from what the user has just achieved.

Example

User creates a Google Review QR.

Appropriate recommendation

"Now that you've made it easier to collect reviews, let's make sure more people actually find your business."

This naturally introduces the Google Listing Scorecard.

---

## **Principle 3**

One recommendation only.

Every screen should have a primary purpose.

Avoid overwhelming users with options.

Wrong

Try these six tools.

Correct

We recommend one next improvement.

---

## **Principle 4**

Every recommendation must answer "why now?"

Never say

"You might also like..."

Instead explain

"Businesses that improve reviews often discover their Google listing is stopping people finding them."

The recommendation becomes educational.

Not promotional.

---

# **The Momentum Chain**

Each tool should have one carefully selected successor.

Not every tool should link to every other tool.

Example

Google Review QR

↓

Google Listing Scorecard

↓

Review Reply Writer

↓

Booking Link Generator

↓

AI Business Assessment

The exact sequence may evolve over time.

The principle does not.

---

# **Recommendation Logic**

Each recommendation should follow this structure.

Celebrate success

↓

Explain why the next step matters

↓

Introduce one relevant tool

↓

Simple action button

Example

Success\!

Your QR code is ready.

Collecting more reviews is one part of the picture.

The next thing we'd recommend is checking whether customers can actually find your business on Google.

Check my Google Listing

---

# **Personalisation Rules**

Recommendations should become smarter where possible.

If the system knows something about the business, recommendations should reflect that.

Example

Restaurant

↓

Recommend Booking Link

Garage

↓

Recommend Instant Quote

Estate Agent

↓

Recommend Valuation Tool

Salon

↓

Recommend Booking Tool

Professional Services

↓

Recommend Review Generator

Recommendations should always feel relevant.

---

# **Avoid These Mistakes**

Never recommend tools randomly.

Never create long journeys.

Never create dashboards showing "progress."

Never gamify the platform.

Never use points.

Never use badges.

Never create unlock systems.

Never hide tools.

Every tool should remain independently accessible.

The Momentum Framework enhances discovery.

It never restricts access.

---

# **Human Psychology**

The framework is based on a simple behavioural principle.

People are more likely to continue improving something immediately after experiencing success.

Therefore

Every successful tool completion becomes the ideal moment to recommend the next improvement.

This is called a Momentum Moment.

The recommendation should occur immediately after success.

Not days later.

---

# **Success Criteria**

The framework succeeds if users naturally explore more of the ecosystem.

It does not succeed by increasing clicks.

Instead, measure:

* Average tools used per visitor  
* Return visitors  
* Time between first and second tool  
* AI Assessment completion rate  
* Consultation bookings originating from multiple tool users  
* Repeat usage of individual tools

---

# **Future Personalisation**

The long-term vision is not more tools.

It is better recommendations.

Eventually the platform should understand:

* business type  
* previous tools used  
* current challenges  
* previous recommendations accepted  
* previous recommendations ignored

The recommendation engine should become progressively smarter while remaining almost invisible to the user.

The user should simply feel:

> "This site always seems to suggest exactly what I need next."

---

# **Final Principle**

This framework must never feel like marketing.

Every recommendation should pass one simple test:

> **If Think Beyond Automation did not exist, would this still be the advice we would give?**

If the answer is yes, it belongs in the ecosystem.

If the answer is no, it is a sales tactic and should be removed.

## **One additional enhancement I'd add**

There's one idea from the restaurant example that I think could become a defining feature of Grow Local Business.

The restaurant owner doesn't simply give away free food. He **recognises where the customer is in the relationship** and changes the experience accordingly.

You can do the same, quietly, without changing the simplicity of the platform.

Internally (not visibly to the user), classify visitors into four stages:

| Relationship Stage | User Behaviour | System Response |
| ----- | ----- | ----- |
| **Explorer** | First tool used | Solve the problem exceptionally well and recommend one logical next step. |
| **Engaged** | Second or third tool used | Make recommendations more tailored to their business type and previous activity. |
| **Committed** | AI Assessment completed or multiple return visits | Offer higher-value resources, invite them to a consultation, or surface relevant case studies. |
| **Partner** | Client | Focus on ongoing value, new tools, continuous improvements, and referrals. |

This relationship model is invisible to users. They don't see stages, levels, scores, or badges. It simply helps the platform decide **what the most helpful next interaction should be**.

I think this is closer to the spirit of the restaurant example than a visible "Business Growth Journey." It preserves the simplicity of Grow Local Business while making every interaction feel progressively more relevant and valuable.
